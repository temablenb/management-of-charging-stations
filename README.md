# Мультиагентная система распределения электроэнергии между зарядными станциями

Имитационная модель сети зарядных станций электромобилей, в которой распределением мощности занимаются не один центральный модуль, а несколько самостоятельных агентов, обменивающихся сообщениями.

**Цель:** оптимизировать распределение электроэнергии между станциями, снизить затраты на зарядку и обеспечить стабильность работы сети (отсутствие превышений лимита подстанции).

**Статус:** проект в разработке. Сейчас реализован прототип на Streamlit (мониторинг, прогноз Хольта–Винтерса, оптимизация мощности линейным программированием, личный кабинет). Мультиагентное ядро и имитационная модель добавляются поэтапно.

## Агенты

| Агент | Роль |
| --- | --- |
| Grid Agent (GA) | Знает лимит подстанции, получает запросы мощности от станций, распределяет мощность между ними и задаёт тарифный множитель |
| Station Agent (SA) | Управляет одной станцией: ведёт очередь автомобилей, строит план зарядки, прогнозирует свою нагрузку и запрашивает мощность у Grid Agent |
| Electric Vehicle Agent (EVA) | Представляет автомобиль: сообщает станции, сколько энергии нужно и к какому времени, и реагирует на тариф |
| Energy Storage Agent (ESA) | Накопитель энергии: заряжается в часы низкого тарифа и отдаёт энергию в сеть в пик, разгружая подстанцию |

## Обмен сообщениями

1. EVA отправляет Station Agent заявку: нужный объём энергии, желаемое время завершения, максимальная мощность зарядки.
2. SA собирает заявки, формирует очередь и план зарядки и передаёт Grid Agent суммарную потребность вместе с прогнозом нагрузки на ближайшие часы.
3. GA сопоставляет запросы всех станций с лимитом подстанции и резервом накопителя, решает задачу распределения мощности и отправляет каждой станции выделенное значение.
4. SA пересчитывает план зарядки. Если выделенной мощности не хватает на всех, очередь корректируется с учётом приоритетов (время ожидания, предоплата).
5. GA формирует тариф станции: базовая цена умножается на множитель, который растёт при высокой нагрузке и падает при низкой.

## Технологии

- Python 3.12
- Streamlit: веб-интерфейс
- pandas, NumPy: обработка данных

## Запуск в Docker

Требуются Docker и Docker Compose.

```bash
git clone https://github.com/temablenb/management-of-charging-stations.git
cd management-of-charging-stations
docker compose up --build
```

Интерфейс открывается на http://localhost:8501. Вход администратора: `admin` / `admin`.

- База данных хранится в папке `data/` на хосте и сохраняется между перезапусками. Путь к ней задаётся переменной окружения `DB_PATH`.
- Состояние контейнера: `docker ps` (через ~40 секунд должно быть `healthy`).
- Остановка: `docker compose down`.

## Допущения модели

- Данные синтетические: нагрузка и поток автомобилей генерируются по сценариям, результат воспроизводится по фиксированному seed.
- Время дискретное, шаг симуляции 15 минут.
- На станции одновременно заряжается не более 5 автомобилей.
- Сеть подключена к одной подстанции с лимитом 420 кВт.
- Базовая цена 10 руб/кВт·ч, тарифный множитель ограничен диапазоном от 0,7 до 1,6.
- Накопитель описывается линейной моделью: ёмкость, ограничения по заряду и КПД.
- Протокол OCPP не поддерживается: система моделирует решения, а не управляет реальным оборудованием.
- Базовый сценарий для сравнения: станции обслуживают автомобили в порядке приезда, лимит подстанции не контролируется, тариф фиксирован, накопителя нет.

## Структура пакета mas

| Модуль | Назначение |
| --- | --- |
| `mas/messages.py` | Типы сообщений между агентами |
| `mas/bus.py` | Шина сообщений и журнал обмена |
| `mas/agent.py` | Базовый класс агента |
| `mas/clock.py` | Часы симуляции (шаг 15 минут) |
| `mas/scenario.py` | Конфигурация сценария, загрузка из JSON, seed |
| `mas/allocation.py` | Распределение мощности: линейное программирование и пропорциональный запасной вариант |
| `mas/tariff.py` | Тарифные зоны суток и тарифный множитель |
| `mas/grid_agent.py` | Grid Agent и журнал его решений |
| `mas/charging_queue.py` | Очередь заявок станции: места, ожидание, приоритеты |
| `mas/charging_plan.py` | Деление мощности станции между автомобилями, расписание, дедлайны |
| `mas/forecast.py` | Прогноз нагрузки (Хольт–Винтерс), температурный коэффициент, часы пика |
| `mas/station_agent.py` | Station Agent: заявки, очередь, запрос мощности, планы зарядки, история и прогноз |
| `mas/ev_agent.py` | Electric Vehicle Agent: заявка, состояния, приём плана и отчёта |
| `mas/ev_behavior.py` | Реакция автомобиля на тариф: сдвиг заявки в более дешёвую зону суток |
| `mas/ev_models.py` | Каталог моделей электромобилей и создание профилей по модели |
| `mas/ev_generator.py` | Генератор потока автомобилей по суточному профилю приездов |
| `mas/storage_agent.py` | Energy Storage Agent: ночной заряд, резерв для Grid Agent в пик |

Тарифный множитель = множитель по нагрузке × коэффициент зоны суток (ночь 0,85, день 1,0, пик 1,15), результат ограничен диапазоном от 0,7 до 1,6.

## Порядок обмена в одном такте

1. Автомобили подают заявки станциям, станции принимают их и занимают свободные места. Накопитель ночью просит у Grid Agent мощность на заряд, а в часы пика предлагает ему резерв.
2. Каждая станция отправляет Grid Agent потребность, прогноз нагрузки и приоритет.
3. Grid Agent распределяет мощность (с учётом резерва накопителя), рассылает станциям выделение вместе с тарифным множителем и командует накопителю, сколько отдать.
4. Станции делят выделенную мощность между автомобилями и рассылают планы зарядки.
5. В конце такта станции проводят зарядку, записывают нагрузку в историю и уведомляют завершивших.

## Запуск симуляции

```bash
python -m mas.cli scenarios/evening_peak.json
python -m mas.cli scenarios/default.json --days 2 --ev-per-day 40 --json result.json
```

Параметры: `--days`, `--seed`, `--ev-per-day`, `--limit` (лимит подстанции, кВт), `--no-storage`, `--warmup-days`, `--json`. Неделя симуляции занимает около 15 секунд.

| Сценарий | Автомобилей в сутки | Лимит, кВт | Что проверяет |
| --- | --- | --- | --- |
| `default` | 70 | 420 | обычный день, редкие пики |
| `evening_peak` | 120 | 420 | выраженные вечерние пики |
| `reduced_limit` | 90 | 300 | сниженный лимит подстанции |
| `many_ev` | 200 | 420 | сеть на пределе возможностей |

Метрики прогона: энергия, выручка и средняя цена для водителей, затраты оператора (закупка энергии по зонам суток и штраф за превышение лимита), пиковая нагрузка, число тактов с превышением лимита, доля автомобилей, успевших к дедлайну, ожидание в очереди, работа накопителя.

## Базовый сценарий и сравнение

Базовый сценарий это сеть без координации агентов: станции получают всё запрошенное, лимит подстанции только измеряется, тариф плоский (базовый), очередь строго по порядку приезда, накопителя нет. Автомобили те же, что в мультиагентном прогоне.

```bash
python -m mas.cli scenarios/evening_peak.json --baseline
python -m mas.cli scenarios/evening_peak.json --compare
python -m mas.cli scenarios/evening_peak.json --compare --save runs --json comparison.json
```

`--save` записывает итоги и состояние сети по тактам в папку `runs/` (по файлу на режим), `--json` сохраняет итоги или таблицу сравнения.

Результаты сравнения за неделю:

| Сценарий | Тактов выше лимита (база / MAS) | Пик, кВт (база / MAS) | Затраты оператора | Цена для водителей, руб/кВт·ч | Успели к дедлайну |
| --- | --- | --- | --- | --- | --- |
| `default` | 5 / 0 | 499 / 420 | −2,7% | 10,00 / 14,63 | 99,8% / 99,8% |
| `evening_peak` | 25 / 0 | 614 / 420 | −5,3% | 10,00 / 14,91 | 99,8% / 98,1% |
| `reduced_limit` | 68 / 0 | 545 / 300 | −15,3% | 10,00 / 14,95 | 100% / 98,7% |
| `many_ev` | 196 / 0 | 650 / 420 | −26,9% | 10,00 / 15,41 | 97,5% / 92,2% |

Затраты оператора: закупка энергии (60% базового тарифа с зонами суток) плюс штраф за превышение лимита (втрое выше закупочной цены). Динамический тариф повышает среднюю цену для водителей, а в самых загруженных сценариях часть автомобилей не успевает к дедлайну: сеть остаётся в лимите ценой отказов.

## Дашборд симуляции

Запуск: `streamlit run gui.py`, вход `admin / admin`, раздел «Симуляция».

На странице выбирается сценарий и параметры (seed, число суток, автомобилей в сутки, лимит подстанции),
запускаются мультиагентная система и базовый сценарий на одном потоке автомобилей.
Показаны сводка, таблица сравнения, графики нагрузки, тарифа и накопителя, очереди станций,
решения Grid Agent и журнал сообщений агентов с фильтрами. Прогоны сохраняются в папку `runs/`
и открываются без повторного расчёта (без журнала сообщений).
